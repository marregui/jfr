The first release of `jfrq`: a command-line tool that asks a Java Flight Recorder recording one
question and answers it with a verdict and its evidence, in text, HTML or JSON.

## Assets

| File | Contents |
|---|---|
| `jfrq-0.1.0.zip` | `bin/jfrq` and `bin/jfrq-live` (with `.bat` for Windows), `lib/` with the three jars. No third-party dependencies. |
| `netty-demo-0.1.0.zip` | The Netty service the [tutorial](https://github.com/marregui/jfrq/blob/v0.1.0/docs/TUTORIAL.md) records; it injects event-loop faults on request. Not needed to analyse your own recordings. |
| `SHA256SUMS` | The SHA-256 of each zip. |

Each zip has a build provenance attestation:
`gh attestation verify jfrq-0.1.0.zip --repo marregui/jfrq`.

## Requirements

- JDK 25 to run. The launchers use `JAVA_HOME` when it is set, otherwise the `java` on the `PATH`.
- Recordings from any JDK 17 or later.

## Install

```
unzip jfrq-0.1.0.zip
export PATH="$PWD/jfrq-0.1.0/bin:$PATH"
jfrq --version
```

## Commands

| Command | Question it answers |
|---|---|
| `jfrq stalls` | Why a thread, such as an event loop, did not return to its idle point: a lock, blocking I/O, a sleep, a JVM pause, or CPU-bound code |
| `jfrq locks` | Which locks threads waited for, who held them, and which holders were themselves blocked |
| `jfrq alloc` | Which threads, classes and sites allocate, in bytes per second; `--baseline` compares two recordings |
| `jfrq health` | What the JVM reported about itself: failed evacuations, full GCs, rising heap floors, throwables by site |
| `jfrq info` | What the file holds: span, threads and their CPU, event counts, and the thresholds that limit what it can show |
| `jfrq-live` | The same questions of a running JVM: it dumps a window of the recording, and `delta` holds only what happened since the last dump |
